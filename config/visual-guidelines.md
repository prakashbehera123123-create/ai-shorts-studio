# Visual guidelines

The full, numeric standard (palette, layout grid, type sizes, visual-form selection, motion, captions) lives in
`docs/CREATIVE_PRODUCTION_STANDARD.md` §4–7. This file is the one-page summary.

- Canvas 1080x1920 (9:16). Zones: step tag/progress (top), question headline, hero visual (≥ 40% of frame), caption zone, reserved Shorts UI area (bottom 18%).
- Identity: dark navy base; semantic accents — cyan = active concept, amber = input, mint = success, coral = failure. Max three accents per frame.
- Motif: the **signal trace** — a thin cyan line with a travelling dot for data/requests/agent actions; enters in the hook, returns in the payoff.
- Choose the least complex visual that shows the spoken sentence: kinetic type → 2D diagram/flow → chart → UI mock → 2.5D → 3D (3D needs written justification).
- Build, don't just cut: one diagram may hold 4–12 s if something meaningful changes every 1–3 s.
- Captions: 2–4 words, word-timed, active word highlighted, never over the hero visual.
- Charts: labelled axes and units, start at zero, source + date chip, "illustrative" for toy numbers. Never fabricate data.
- Screenshots: self-captured, public/demo data only; blur personal identifiers. No real logos or imitation vendor UIs.
- Avoid: generic AI-looking stills that do not illustrate the claim, decorative motion, tiny text, non-executable decorative code.
